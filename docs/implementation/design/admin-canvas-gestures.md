# Admin 语义画布的手势

状态：已修（2026-09-22）。用户在真机上连报三次"拖不动"，同一类病因：**状态没人清，或者两套实现在分工**。

## 症状（用户原话）

- 一次展开好几个文档之后，页面拖不动了；
- 单指滑动时"**不能退出，鼠标到哪它到哪**"；
- 鼠标停在某个位置，**双指拖动几次就卡住，换个地方就好了**。

## 病因

1. **丢掉的 pointerup**：`pan` 留在原地，此后**每一次鼠标移动都在平移**，不管按没按键。
   真机日志：15 次 `pointerdown` 只有 14 次 `pointerup`；最近 200 次 `pointermove` 里 189 次
   "没按键"，而相机在这段时间变了 154 次。
2. **空白处的鼠标平移交给了 G6 的 `drag-canvas`，而它在这里不工作**：同一次真实鼠标拖拽，
   从文档卡片按下能拖动，从空白处按下相机一动不动。
3. **滚轮有两套实现按位置分工**：落在卡片上走本桥，落在空白处走 G6 的 `scroll-canvas`。
   两套各自都会卡，于是表现成"这个位置拖几次就不动，挪开又好了"。

## 决定（这些是规则，不只是这次的修法）

- **画布手势只有一层，而且由应用自己拥有。** `drag-canvas` / `scroll-canvas` / `zoom-canvas`
  全部不使用：一层我们不控制、状态又清不掉的实现，迟早留下一种"拖不动"。
- **一次拖动必须能自己结束。** 见到"没按键"的移动即判定拖动结束；窗口失焦、`pointercancel`
  直接放弃。松开的信号为什么丢不重要——下一次没按键的移动就是证据。
- **空白处按下不立刻抢指针。** 语义节点就画在空白处，一按下就 `setPointerCapture` 会把
  `pointerup/click` 重定向到容器，G6 再也收不到节点点击，**展开与收起会整体失效**（顾问在提交前
  拦下的坑）。先记起点，移动超过 `CANVAS_DRAG_THRESHOLD`(3px) 才算拖动，否则按点击放行。
- **按帧合并 + 兜底。** 位移按 `requestAnimationFrame` 每帧最多应用一次；同时挂一个 100ms 计时器，
  rAF 迟迟不来（后台标签、极端掉帧）也要把累积的位移应用掉。

## 验证

- 真机真实输入：改前"按下 + 两次没按键的移动"把相机推了 100px / 120px；改后同一序列**纹丝不动**。
- 空白处真实拖拽：改前相机不动，改后能动。
- 性能同批次实测：19 篇文档全开，打开一篇 16–26ms、收起 4–6ms，最差帧 38ms，>50ms 的帧 0 个。
- `internal/adminui/bundle_test.go` 把上面四条规则钉成断言（禁 `drag-canvas`/`scroll-canvas`/
  `zoom-canvas`/`trackpad-pan`/`trackpad-zoom`；必须 `event.buttons === 0`、`CANVAS_DRAG_THRESHOLD`、
  `gestureTimer`、`isCanvasControl`）。加回去跑过，断言确实红。

## 边界

- 触控板 pinch（浏览器映射为 ctrl+wheel）走本桥；触摸屏多点触控没有专门处理，桌面 Admin 未纳入。
- 卡顿的首次判断（DOM 卡片在相机变换下的重栅格化）见
  [Admin 语义画布的性能](./admin-canvas-performance.md)。
