# Agent 发什么，引擎展开什么

状态：**讨论稿**（2026-09-21 立判据；两项表面变更待授权）。

## 一句话

判据是**语义由谁决定**：

- 需要一个引擎猜不出的自由选择（名字、边界、归属、裁决）→ **必须是 Agent 的一句**；
- 完全由已写入的行状态 + 已定规则推导出唯一结果 → **收进引擎**，作为行写入的
  **确定后果**。

这跟[架构原则](../product/architecture-principles.md) §1 的判据是同一条：确定后果必须和
触发它的行写入**同一个事务**，不能让 Agent 再补一句去拼。

## 分界

| 事 | 谁 | 为什么 |
|---|---|---|
| 选库/表、决定写什么内容 | Agent | 语义 |
| 节点起名、定层级、改名、移动 | Agent（`CREATE ROUTE` / `ALTER ROUTE`） | 引擎猜不出名字与归属 |
| 拆分边界、合并对象、冲突裁决 | Agent（`SPLIT` / `MERGE` / 请求裁决） | 语义判断 |
| 叶子生灭、挂载与摘除 | **引擎** | 1:1 之后叶子是行的属性，不是独立实体 |
| 删行引发的归档、删叶、剪枝、摘链接、删 history | **引擎** | 行的确定后果，见[行删除](../product/row-delete-archive.md) |
| revision 推进、history 追加、变更信封 | **引擎** | 机械 |
| 空节点/空分支清理 | **引擎** | 没有自由度 |
| 扇出上限、权限、revision guard | **引擎拒绝，不猜** | 不变量 |

一句话记法：**挂在行上的东西归引擎，需要起名和归属的东西归 Agent。**

## 由此改变的两件事（待授权）

1. **`DELETE ROUTE` 从 Agent 表面退役。** 删空节点没有自由度，是删行或重构的确定后果。
   留着它等于开出第二条路径：Agent 能删掉还挂着 live 行的节点，引擎只能在「拒绝」和
   「级联删行」之间选，两个都是坏语义。空分支的清理由引擎在子树变空时顺手做；要重构树
   走 `PLAN ROUTE MUTATION`。
   现状：语句在核心里已实现（parser/executor/security 都认它），但**没有出现在任何现役
   文档或 Skill 里**——退役是把它从表面收进引擎，不是删能力。
2. **INSERT 允许隐式建路径。** Agent 写出的路径名本身就是它的语义选择，所以 INSERT 指向
   一条尚不存在的完整路径时，在同一事务里补齐中间节点与叶子是确定后果，不违反「引擎不猜
   语义」。显式 `CREATE ROUTE` 保留给「先搭空骨架」的场景。

## 待定

- 空分支自动清理的触发面：任何让它变空的操作（删行、MOVE、`APPLY ROUTE MUTATION`）都做，
  还是只在删行路径上做；
- 两项表面变更都要动 MSQL 与 Skill，需与契约版本一起走。
