# Feature 产品与用户故事门禁

状态：已确认；适用于所有新 Feature、返工和架构替换。它与测试门并列，不能由“测试全绿”替代。

权威产品定义见 [AI-native 产品宪章](../product/ai-native-product-charter.md)。
测试与合入规则见[小 Feature TDD 与合入协议](./feature-tdd-protocol.md)。

## 规划与授权顺序

新一阶段不得从“还有代码缺口”直接进入实现，必须按以下顺序进行：

1. 先与用户讨论后续 Feature 的产品目标、用户故事、边界、依赖、顺序和验收方式；
2. 形成标记为“讨论稿”或“待批准”的 Feature 计划，供用户 Review；
3. 用户可以调整、拆分、重排或删除 Feature，此时不编写产品代码或实现性测试；
4. 只有用户明确表示“可以执行”、“开始实现”或同等授权后，才能开始实现；
5. 授权只覆盖已 Review 的范围。实现中如果出现新的架构选择、产品边界变化或显著扩项，必须回到规划阶段再次 Review。

在用户批准前，可以进行只读的代码与现状调查、风险分析和计划文档整理；这些工作不能被表述为 Feature 已开工。

## 开工前门禁

Feature 分支和实现计划必须先回答：

1. 它改善哪些用户故事（使用 `US-*` ID）？AI 或人将少做什么、多得到什么？
2. AI 从冷启动到完成目标的标准 SQL transcript 是什么？
3. 它作用于 Database、Table、Row、关系、Route Tree、Schema 还是物理引擎？边界是否混淆？
4. 它怎样影响 Row revision、Route membership、历史、事务和失败恢复？
5. AI 每一步最多看到多少节点、RowID 和正文？Route Frame 如何保持有界？
6. 是否把 Row/chunk/正文向量、相似度结果或全库 prompt 扫描当作事实权威？若使用
   Route predictor，是否只返回有界位置并保留 provenance、snapshot 和 Router 回退？
7. 是否让 Agent 绕过 MSQL，或让人承担本应由 AI/引擎完成的数据库工作？任一出现即否决。
8. 是否把 SQLite、某个 Provider、某个宿主或临时 benchmark 变成产品语义？若是，必须重设接口边界。
9. 最小验收旅程、错误注入、回滚测试和旧数据兼容证据是什么？
10. 它是否符合最终产品理念，而不只是填补当前代码缺口？
11. 是否只有一个主要结果、一个独立 RED 入口和一个主要故障域？若不是，先拆分。

没有故事 ID、标准流程和可验证验收，Feature 不开工。

## 架构变更披露

引入或替换持久化后端、查询主路径、索引算法、模型调用方式、许可证或宿主边界前，必须在实现前明确记录并向用户说明：

- 为什么需要改变；
- 它是否只是可替换原型；
- 它会不会改变 AI 看到的协议和产品形态；
- 替换条件、退出路径和新增风险；
- 用户是否已确认。

SQLite 一类实现选择不能隐藏在 Feature 列表里，也不能因 ADR 已提交就视为用户已知。

## 完成后门禁

合入主分支前必须提供：

1. 从 Canonical Skill/宿主入口开始的真实 AI 用户旅程证据；
2. 实际执行的 MSQL、每步有界结果、最终 Row/Schema/Route 状态；
3. 对开工前每个 `US-*` 的逐项验收结果；
4. split/merge/update/delete 后没有陈旧 Route membership 或关系的完整性证据；
5. 权限、冲突、超限、中断和重试路径的结构化错误证据；
6. 无 Row/chunk 向量权威、无隐藏旁路、predictor 可回退且存储后端不泄漏到产品协议的审计；
7. 文档、测试、实现和当前 Feature 状态同步；
8. 对未满足项明确标记“未完成”，不得用 benchmark 分数覆盖。

## Feature 模板

```text
Feature:
规划状态: 讨论稿 / 待批准 / 已批准
目标用户故事:
用户结果:
标准 MSQL 旅程:
语义树/Schema/Row 影响:
上下文预算:
失败与恢复:
永久边界审计:
架构选择与用户确认:
用户执行授权:
唯一主要结果:
明确不做:
RED 测试、命令与当前失败证据:
开工前结论: PASS / REVISE / REJECT

完成证据:
GREEN/REFACTOR 与完整测试命令:
故事逐项验收:
旁路与语义权威审计:
剩余偏差:
完成后结论: PASS / INCOMPLETE
```

只有“完成后结论：PASS”的 Feature 才能被计划、发布门和文档标记为完成。
