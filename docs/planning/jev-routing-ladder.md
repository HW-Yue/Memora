# jev 分流阶梯：什么时候走树、什么时候用 jev、剩下的活怎么排

状态：**实现计划**（未开工，等开工）。契约细节见 `docs/planning/whole-layer-read.md`；
标签质量见 `docs/planning/route-purpose-contract.md`（已上线）。

## 分流阶梯：判据在输入形状上，不用"试了再说"

1. **输入含专有字面量**（公司名、人名、项目名）→ 直接关键词 `RECALL`，命中就回表，**根本不进树**。
2. **输入是模糊近义**（"类似的""那种感觉"）→ `RECALL … NEAREST`，同样只为拿位置。
3. **输入是类目型**（"我有哪几段 X""关于 X 的缺口/决定"）→ 走树，这是树的本命。**默认执行器是 jev
   走树**；agent 自己逐层走降级为 fallback 与调试路径。
4. **宽意图不预先分流**：从 Database 层起跑**一次** jev，靠 `empty` 剪枝自己收敛。
   "第一层就散成多库多表"恰恰是 jev 最稳赢"agent 自己逐层走"的场合。
5. **不把 jev 改成打分选 top-k**：`set`（"答案在不在这里"）是对的形状。实测 9 个候选并成一个请求
   无判别力（.47–.66、地板 .37），那条边界就是这条规矩的证据。

> **更正**：`docs/decisions.md` 里"宽意图是负收益、不该走 jev"那条结论**被推翻**——它依据的 65.1 s
> 来自带读取端上限的旧版（漏答案、agent 手工补）。修掉上限后，同一宽意图整棵树的**脚本**时间是
> 6.22 s 并命中两行。**但"修好之后的 agent 级总时长"还没实测**，那是这一块的验收项（见下）。

## 剩下的话，按这个顺序

1. **回填 44 条 Route 的 purpose/aliases**——**前置，不是收尾**。标签质量是 jev 准确率的天花板：
   实测同层里只要有一条真描述，切分就干净（.10 对 .88、地板 .06）；全是复读时它只能 `undecided`。
2. **让 `SHOW ROUTES` 的叶子顺手带出 `row_id`**——一处改动两路受益：jev 那 35 条 `OPEN ROUTE` 归零，
   **自己逐层走的模型也省**（列表里就有行号，不必再开叶子）。收益最大、风险最低。
3. **`whole-layer-read.md` 那一包**：删读取端宽度/次数/深度三个上限、只留时间阀；没走完的分支不进
   `landings`；`visited` 防环 + 数据损坏告警；落点带 `database`/`table`；Skill 写清"定位 vs 回表"。
4. **落点按 `(database, table)` 聚合 + 带列名**：等第 2 步落地后，这基本是纯格式化——35 个落点真实是
   6 张表上的 6 组 row_id，一表一条 `WHERE row_id IN (...)`；顺手带上列名，省掉 agent 写回表 SQL 前
   还要 `DESCRIBE` 一轮。
5. **不做**：jev 的缓存、并发、小模型降级、阈值调参——1.4 s 与 6.2 s 都不是瓶颈，现在做是提前优化。

## 坑（进契约或进实现）

- **`empty` 现在是静默的**：判错一次，整条分支无痕消失，契约里只有"停在这里"、没有"我剪掉了什么"。
  必须给剪枝留一条**可审计记录**，否则漏答永远无法归因，只能靠人肉发现（旧版那次就是这样被发现的）。
- **报进 `undescribed_at` 的层必须强制按 `undecided` 整层展开**，不许采信 jev 在这一层的判断——
  否则那是拿 name 当 purpose 在判，坏标签会**直接变成漏答**。这是第一块的一个后续小改。
- **无上限 + 按量计费**：时间阀只兜 provider 挂死，兜不住"13 次决策变 130 次"的账单。要的是决策次数的
  **观测与告警**，不是再塞一个上限。
- **上线"落点只有叶子"之前先扫存量**有没有非叶子承载事实（真库现在 `orphan_rows`/`multi_leaf_rows`/
  `mismatched_mounts` 都是 0，干净；但这条要进判据）。
- **验收项**：修好之后要再做一次**不带上下文的 agent A/B**（同一组跨库三问），用真实总时长回答
  "jev 到底快不快"——脚本层的 6.22 s 不等于 agent 层的结果。
