# 中文与短词的召回：为什么「实习经历」搜不到

状态：**诊断已定，方案待开工**（2026-09-21）。用户在 Admin 搜索页实测发现的问题。

## 实测（`me` 库，关键词臂）

| 查询 | 结果 |
|---|---|
| `oppo` | 命中 4 条（正文里有 "OPPO"） |
| `实习` / `经历` / `后端` | **被拒绝**：`RECALL needs at least 3 characters` |
| `实习经历` | **空** |
| `实习 经历` | **空** |
| `实习经历`（向量臂） | 命中：`实习/OPPO`、`实习/悠悠有品` 等 |

## 病因（两层，都不是"没做切分"这么简单）

1. **索引是 trigram（连续子串）**：FTS5 的 trigram 分词器把正文切成 3 字滑窗，所以
   - **1–2 个字符的查询永远匹配不到任何东西**——这就是那条"至少 3 个字符"的拒绝存在的原因：
     空结果读起来就是"没找到"，宁可拒绝；
   - 更长的查询被当成**一整段连续子串**：`实习经历` 要求正文里真的连着出现这四个字，而没有任何
     正文（每行只索引 `title` + `summary`）是这样的——语义树节点叫 `实习`、表描述写
     "实习与工作经历"，**树节点名与表描述都不在被索引的正文里**。
2. **查询端不切分**：中文没有空格，`实习经历` 就是一个词，引擎不会把它拆成 `实习` + `经历`。

用户猜的两条里，**"向量没做好"其实是他跑着的 Admin 是旧 bundle**（前端编在二进制里，没接上
向量支路），重启后同一个问句走向量臂是能答的；**"没做切分"是真的**。

## 顾问的结论（2026-09-21）

- **只降阈值 + 短词走扫描，修不好他举的那个 bug**：`实习经历` 是 4 个字符、每个词都 ≥3，
  按"最短词选路径"的规则仍然走倒排，仍然返回空。
- 真正的病因是两条：**索引面太窄**（树节点名、表描述不进正文）+ **中文没切分**。
- 最大风险：**修法与病因错配**，制造"已修复"的假象。
- 次生风险：`LIKE` 扫描没有相关性信号、只能按 `unit_no` 排序，喂给 RRF 相当于**注入一条伪排名臂**，
  会稀释向量臂的真信号。

## 方案（按顾问给的顺序）

1. **索引面**：召回单元的载荷并入**语义路径的节点名**（每行自己的位置，信息量最高）。
   表描述**不并入**——它对该表每一行都一样，只会让"实习与工作经历"这种词命中整张表，是噪声。
   代价：载荷变了 → `content_hash` 变 → 所有向量变陈旧 → 宿主排干会重嵌（43 个单元，机制现成）。
2. **查询端切分**：中文查询按 **2 字滑窗** 拆（`实习经历` → `实习` / `习经` / `经历`），`OR` 召回。
   用 2 字而不是 3 字，是因为 trigram 索不了 2 字词、而 3 字滑窗（`实习经`/`习经历`）又几乎不可能
   命中；2 字窗才是中文的最小可用粒度。
3. **短词兜底**：最短词 <3 字时走**有界 `LIKE '%词%'` 子串扫描**（受 `select_scan` 与 `LIMIT`
   双重约束，按 `unit_no` 排序保证确定性）。**并且**——它是无序臂，融合时**不能冒充排名**：
   有序的两臂照旧 RRF；含无序臂时改成"向量臂的顺序在前，无序臂只贡献成员资格（去重后按
   `unit_no` 追加）"。
4. **最低长度 3 → 2**（用户要求）：1 个字符仍然拒绝（它几乎匹配一切）。注意这条**必须**和第 2、3
   条一起做——单独降阈值只会把"明确拒绝"换成"静默空结果"，比现在更糟。
5. **Admin**：搜索框最低 2 个字符，并在只有关键词臂可用时说明"2 字中文靠子串扫描，
   两字以下的关键词召回本来就答不了"。

## 验收

- `实习经历` / `后端实习` / `实习` / `经历` 四条都能命中那两条实习（关键词臂或两臂融合）；
- `oppo` 的命中集合与顺序不退化；
- 短词扫描**不改变**向量臂的排名信号（含无序臂时的融合顺序有测试钉住）；
- 载荷变更后 `doctor` 的 `units_without_vectors` 归零（重嵌完成）、`vector_index_drift` 为 0；
- 重启 Admin 后页面上重测同样四条（排除旧 bundle 干扰）。
