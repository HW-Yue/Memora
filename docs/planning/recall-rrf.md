# 召回融合：RRF 进引擎，只改顺序

状态：**方案已定（A）**，2026-09-21 用户拍板。RRF 进引擎，只改顺序，不外露任何数字。未授权开工。

## 要解决的问题

两臂并集之后，现在按「表名 + 路径」**字典序**输出（`recallUnion` + `mergeMergeRows` 那条排序）。
这个顺序与相关性无关：一个主打准确检索的产品，"前 10 条"不该由表名和路径字符串决定。
想要的收益是**前 10 条更准**——RRF 正是为这件事存在的。

## 方案 A（顾问推荐，本文档以此为准）

- **两臂各自按自己的相关性序取候选**：向量走 vec0 距离序（现在就是）；关键词改走 FTS5
  `bm25()`——现在是 `ORDER BY u.unit_no`（插入序），当时的理由是"不像 FTS rank 那样会被误当成
  相关性判断"，在 A 之下这个顾虑消失，因为**名次只喂融合、不出门**。
- **融合 = RRF**（`k = 60`），**只用名次，不用分数**：
  `score(d) = Σ_arm 1 / (k + rank_arm(d))`。这里的 `rank_arm(d)` 是「d 在该臂自己那份有序列表里
  排第几」，臂用来排那份列表的量各是各的——向量是 vec0 的距离（小者在前），关键词是 FTS5 的
  BM25 分（大者在前）。RRF 要的只是序号，所以两个**不可比**的量不需要换算成共同尺度，
  也没有权重可调；这正是它适合这里的理由。
- **平分回落到现有的「表名 + 路径」字典序**，把确定性保住：现有 `determinism_test` 与"同样查询
  同样输出"的保证不能跟着一起失效。
- **`LIMIT` 仍是输出截断**。两臂各取多少是内部候选深度，不是契约：向量臂现在是
  `max(2n, n+8)`（上限 `maxVectorCandidates = 4096`），关键词臂建议同口径。
- **一路答不了 → 整条语句失败**（不变，不给"看起来完整的半份答案"）。
- **契约表面不变**：返回的仍然只有位置（每段 `name` + `route_id`，末端 kind/object_id），
  没有分数、距离、名次、原因、正文。

## 方案 B（用户想要，顾问明确反对）

返回**每臂名次 + 融合分**。反对理由：分数一旦进入契约，模型和下游就会开始按它判断、按它截断、
按它解释"为什么这条更相关"——那正是旧 F21/F23 被撤销的路径，而且**外露的字段删不掉**，
从此不可逆。ADR-0012 今天明文写着「禁止把分数或距离外露；不设置或调优融合权重」。

## 方案 C（宿主侧 RRF）

分别调两次单臂，宿主自己融合。更糟：逼关键词臂改成相关性序、把融合逻辑复制进每个宿主，
结果是契约没动、语义散了，还失去确定性测试的保护。只在宿主真要做多源编排时才考虑。

## 改动范围（按 A）

- `internal/sqlstore/recall_read.go`：关键词臂改 `ORDER BY bm25(mem_recall_fts)`；把"按路径排序"
  从臂里挪出去（臂只负责自己的相关性序），在代码里写明前提——名次只喂融合、不外露。
- `internal/msql/executor/archive.go`：`recallUnion` 换成 RRF；`mergeRecallRows` 的字典序排序
  降级为**平分的 tiebreak**。
- **单臂语句的顺序也跟着变**：否则同一句话加不加另一臂会给出两种排序。单臂 = 只有一路参与的
  融合（等价于该臂自己的序 + 字典序 tiebreak）。
- 测试：`internal/sqlstore/recall_keyword_test.go` 的 `TestKeywordRecallScopeAndOrder` 现在钉死
  "输出按路径有序"（`wide[0] == "root/alpha"`），必须按新契约重写；保留
  「输出字段里不得出现 score/rank」的断言，并**补一条**"融合顺序变了、字段集合不变"的测试；
  determinism 测试保持通过。
- 文档：`docs/query/msql.md`（并集那段）、`docs/query/retrieval-routes-jev.md`、ADR-0012 的
  "禁止外露分数"改写为「**名次可内用、不可外露**」；新增一条 ADR 把 A/B 的边界写死。
- Admin 搜索页：现在是自己交错合并，落地后应改成用引擎的融合顺序（少一层自己发明的排序）。

## 为什么这是 ADR 级

ADR-0012 明文禁止外露分数/距离、禁止调融合权重；ADR-0007 记载旧 F21/F23 因为"相似度融合成为
查询主路径、候选当答案来源"被撤销。A 不碰这两条禁令（不外露、不调权），只把**排序**从字典序
换成基于名次的融合——但它仍然在修订召回契约的表述，所以要一条新 ADR 写明「名次内用、
不外露」，以及为什么 B 不做。

## 最大风险（顾问指出）

**契约腐蚀**：A 一旦落地，「引擎内部已经有分数了」会成为下一次要求外露的论据，B 会以
"只露一点点"的形式回来。所以新 ADR 必须现在就把边界写死。
