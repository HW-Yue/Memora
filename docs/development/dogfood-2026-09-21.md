# 实测缺陷报告：以真实 agent 身份用 skill + 引擎

状态：**进行中**（2026-09-21 起）。被测对象：`skills/memora/`（引擎仓库内的规范技能）、
发行仓库 `~/Developer/memora-skill`、本机实际安装的三处 `~/.agents|.claude|.codex/skills/memora`。

方法：不读源码先当用户——照 SKILL.md 写什么就做什么，卡住就记一条。

## D1 · 本机安装的 skill 落后 M4–M7 全部读面（严重）

**现象**：`~/.agents/skills/memora`、`~/.claude/skills/memora`、`~/.codex/skills/memora`
三处安装的 `SKILL.md` 是同一份 **471 行**的旧版本（文件时间 2026-09-20 23:31），
而引擎仓库的规范版本是 **618 行**。关键能力在已装版本里**一次都没出现**：

| 关键词 | 已装版本 | 引擎版本 |
|---|---|---|
| `RECALL` | 0 | 5 |
| `ACCEPT VECTOR` | 0 | 1 |
| `SHOW PENDING VECTORS` | 0 | 2 |
| `SHOW ARCHIVE` | 0 | 2 |
| `REPAIR LINKS` | 0 | 1 |
| `vectors_not_ready` | 0 | 1 |
| `embedding` | 0 | 9 |

**影响**：真 agent 读这份 skill，就不知道召回、归档读面、链接懒修复、向量提交与排空的存在，
只会用 M3 之前的写法——**功能实现了但用户用不到**。

**修**：把规范版本同步到三处安装位（保留备份），并让"落后"可被检测（见 D3 的修法）。

## D2 · 发行仓库 `memora-skill` 仍在教已被删除的命令（严重）

**现象**：`~/Developer/memora-skill` 的 `SKILL.md` 是 **762 行**的旧内核版本，正文里写着
`memora assimilate`、`capture`、`decide`、`feedback`、`maintain`、`reflect`、`upgrade`，
以及 `doctor repair` 与 `memora upgrade --plan/--apply`。这些命令在现役 CLI 里**已经不存在**
（引擎 devgate 的删除清单里明确禁止这些字符串再出现在技能文档里）。

**影响**：照这份文档操作会**每一步都失败**。三份副本各说各话本身就是缺陷。

**修**：以引擎仓库 `skills/memora/` 为唯一真源，覆盖发行仓库内容并提交。

## D1/D2 的修法已落地

- 三处实盘安装位同步到规范版（备份留在 `/tmp/skill-backup-20260921-180938/`）；
- 发行仓库同步并提交（`faefd30` + 后续一次）；
- **新增 `scripts/sync-skill.sh`**：一条命令管整条链，`--check` 只报告不改动。它就是 D4 的修法。

## D5 · 适配器之间的 `openai.yaml` 早就分叉了（中，由 D4 的修法当场抓到）

**现象**：`scripts/sync-skill.sh --check` 一跑就报出——codex 适配器的 `agents/openai.yaml`
与规范版不同，claude-code 适配器**根本没有这个文件**，而且它的 `manifest.json` 里也没登记。

**影响**：两个适配器携带的文件集不同，而门禁的共享清单恰好不含这个文件，所以谁都发现不了。

**修**：同步文件、把条目补进 claude-code 的 `manifest.json`（路径前缀跟着各自 adapter 走）、
`--check` 现在为零漂移。

## D3 · `check.sh` 指向一个不存在的 Release（中）

**现象**：`skills/memora/scripts/check.sh` 在没装 CLI 时输出
`"release_url": "https://github.com/HW-Yue/Memora/releases/latest"`，
但引擎仓库的 `.github/workflows/release.yml` 是个**拒绝发布**的桩（打 `v*` tag 会明确失败）。

**影响**：agent 会让用户去一个**没有产物的 release 页**下载；指导是错的。

**修**（已落地）：改成输出 `install_url` 指向 README 的源码安装段，并注释写明"等发布链路
落地后换成真实 Release，否则用户会被指向 404"。

## D4 · 没有任何"已装 skill 是否落后"的检测（中）

**现象**：三份副本分叉了却没人知道。引擎仓库的 devgate 只保证
`skills/memora/*` 与两个 adapter 副本 + manifest 摘要一致，管不到用户机器上的安装位。

**修**（已落地）：新增 `scripts/sync-skill.sh`，一条命令管整条链——

```sh
scripts/sync-skill.sh --check                      # 只报告漂移（适配器 + 可选目标目录）
scripts/sync-skill.sh                              # 同步仓库内的适配器副本
scripts/sync-skill.sh --install ~/.agents/skills/memora
scripts/sync-skill.sh --publish ~/Developer/memora-skill/memora
```

`--check` 是入口：三份副本分叉这件事因此**可查**，而不是靠人记得重装。
