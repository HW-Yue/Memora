## 已修（按根因归类）

**引擎**
- 读面报错说清替代做法：`WHERE … IN` → 指出 `row_id` 单等值 / 一语句一行 / `--input` 数组；
  `LIMIT` 超预算 → 指向 `SHOW CONFIGURATION` 与 `ALTER CONFIGURATION QUERY_BUDGETS`；
  投影 `route_paths` → 说明它随行附带、不可投影。
- **`truncated` 只有一种含义**："还有没返回的"。原先两个面用 `len(items)==limit`，满页即报 true；
  现在多取一条再丢弃，融合臂各多取一条。真机：`RECALL 原醛 LIMIT 1` → false，`悠悠有品 LIMIT 1` → true。
- **截断可执行**：`output_truncated` 通知里带 `details.enumerate_with`
  （`SHOW ROUTES FROM TABLE … AT ROOT LIMIT :limit`），读者不必记住"只有树能枚举完"。
- **读面带出上限与新鲜度**：`columns[].max_characters`（Unicode 码点）与点查
  `row_detail.created_at/updated_at`。前者让"约 1000 字 vs `TEXT(2500)`"可核对，后者让
  "自述是活记录"的行能被判定是否真的更新过（`revision` 会长期停在 1）。
- `check.sh` 报 `"daemon": "running" | "not_running"`：`ready` 曾与 `running:false, pid:0` 同时出现，
  而 Skill 把 `ready` 描述成"CLI 与 daemon 一致"。

**Skill**
- 两个照抄即报错的 `RECALL` 示例（`LIMIT :limit`）。
- `--input` 数组：**每个元素按同序号绑定自己的 `parameters.named`**；补不同值的示例。
- 预算：五条预算（含此前从未写出的 `select_scan` 1000）、**按语句**计、何时才需要读。
- 普查：无 `WHERE` 的 SELECT 合法且返回 `row_id`+`route_paths`；**一次请求普查全库所有表 + 一次点查**
  是最短诚实路径（第 4 轮实测 5 次 shell 调用答完三问）；超过 `select_rows` 的枚举器是语义树。
- 五态检测器与处置；`unknown` 带 `reason`；`skewed` 要先重启 daemon 再读。
- `TEXT(n)` 单位是**码点**；四条豁免命令（`daemon stop`/`parse`/`instance destroy`/`jev_*.py`）。
- 文档漂移：产品文档、`AGENTS.md`、Skill 自带 `references/product-manual.md` 的"召回待实现"全部更正
  （只改事实句，路线意图保留并标注已交付）。

**防复发**
- `internal/skilldoc`：逐个检查 SKILL.md 里**全部 32 条 `memora` 命令**（对象/数组输入、裸语句、
  plan、工具调用），语句必须能解析、参数必须恰好对上，**未识别的形状直接失败**；扫描**所有**围栏。
  它做的是静态检查（解析 + 参数绑定），不执行——注释里写清楚了。

## 记录下来的边界（不是 bug）

- `SELECT` 不加 cursor：要先把扫描顺序写进永久协议，等于在"点查 + 有界普查"这个动词里重建语义树的翻页。
  触发条件（表超过 ~100 行且树 walk 往返成为负担）与将来的做法（给 `row_id` 一个承诺不变的序，
  加 `row_id > :x` 比较，不要 token）写在 `docs/decisions.md`。
- `SHOW ROUTES … AT ROOT` 返回根的孩子，保留形状（子行的 `parent_id` 即根 ID）。
- `SELECT` 信封的点查行会重复 `columns`/`row_detail`（约 1.5–2KB/行），属开销不属正确性。
- `COMPACT` 不会丢语义字段（核查过：`anti_scope` 非空时总写入）；将来裁剪不得动 scope/purpose。
- 本机 `~/Developer/memora-skill`（分发用的另一个 git 仓库）停在 2026-09-21 21:19 的提交，
  今天拆出来的 `references/*` 还没发布过去。**这是发布动作，不是漂移**——`sync-skill.sh --check`
  不覆盖它（`--publish` 才写，而且要求那个仓库自己提交），在用户授权发布之前不动它。

## 第 6 轮：写入与失败路径（一次性实例）

方法：`HOME=$(mktemp -d)` + `memora init`，绝不动真实实例。走完 建库建表 → 建 Route 树 →
写入 992 码点中文行 → REVISE → 再写一行 → 尝试 SPLIT/MERGE → 删除 → 用五种读面确认不可达 →
`SHOW ARCHIVE`/`OPEN ARCHIVE` 复原 → 逐步重建，再逐条踩失败路径（陈旧 revision、超上限、
L0 尝试写、中途 `daemon stop`、语法错误）。

**已修（Skill）**：INSERT 示例缺 `summary`（照抄必被 `constraint_violation` 拒绝）；「每个 UPDATE 都必须
写 title 和 summary」这句引擎并不强制、且与两段后的 UPDATE 示例自相矛盾；`AS OF REVISION :n` /
`AS OF COMMIT_SEQUENCE :n` 语法缺失（且 AS OF 读的 `links` 为 null、`route_paths` 为空）；
`SHOW ARCHIVE` 只给了 `FOR ROW` 形式（而**不带** `FOR ROW` 才是发现删除的唯一途径）、归档值按
`column_id` 键控、归档记录 `row_state` 仍写 `live`；普查段「没有只读续读」与紧接的「用树 walk」
自相矛盾；`PLAN ROUTE MUTATION` 只示范 MOVE 却声称支持 SPLIT/MERGE（4 次调用白花）；
三种路径拼写不一致（`route_paths` 无根 / 召回 `path` 带字面 `root` / 归档 `/root/…`）；
`daemon status` 与 `version` 未列入 sanctioned 列表；写入会在 stderr 打非 JSON 提示
（provider 半配置），`MEMORA_EMBEDDING=off` 可关掉。

**已修（引擎）**：`row_detail.display` 原先按**本次投影**生成（只查 `title` 就没有 `summary_column`），
改为按**表的角色**生成；`memora --version` 不再报 "unknown command"。

**验证到的正面结论**：`value_too_long` 与 `max_characters` 都以 Unicode 码点计（992 汉字＝2900 字节，
远在 2500 之下）；删除后五种读面全部不可达、只有归档可达且内容逐字节一致；`route_path` 与
`route_leaf_ids` 在 INSERT 上都可用；失败路径的报错都带可执行信息（陈旧 revision 报出实际 revision，
L0 写报出需要的等级）。

## 第 8 块：Skill 改成分层加载（渐进式披露）

顾问的判断（用户提出"做渐进式披露"后咨询）：

- **按"约束 vs 步骤"切，不按话题大小切**。留在常驻文件里的是**违反了会静默出错**的一条条约束：
  授权对象规则、stdout/stderr 分开、禁止读物理文件、可用命令清单、L0/L1/L2 上限、Provider 密钥。
- 回答"**怎么做 X**"的一切（语法、示例、参数绑定、引号规则、路由 bootstrap）进 `references/`。
  判据：**如果 agent 在猜错之前无法知道自己需要这份文档，就留在常驻文件**；如果"需要它"从用户请求里
  一看就明白，就做成链接。
- **目标 4–5 KB，不是 13 KB**——13 KB 只是观测到的额度，还会被 frontmatter、别的 skill 和宿主前言分摊。
- **触发强度在 frontmatter 的 `description` 里**（单独注入、不参与截断），不要动它。
- 最大的坑：**常驻文件看起来自给自足**。只要里面留了一条完整可用示例，宿主就会照着它模式匹配、
  再也不打开 reference——同样的即兴，只是更有底气。所以 spine 里**一条完整语句都不留**，
  每节只留一行路由："要写 Row → 先读 `references/write.md`"。
- 第二个坑：`internal/skilldoc` 必须**连 references 一起扫**，否则挪出去的 32 条示例一搬家就失去验证。

**落地**：`SKILL.md` 从 **62.7 KB / 999 行** 变成 **4.1 KB / 62 行**（约束 + 路由表；顶部那条
"正文被截断就去磁盘读全文"的止血提示已删除，因为 4 KB 不会再被截断）。步骤拆成六份按需文件：
