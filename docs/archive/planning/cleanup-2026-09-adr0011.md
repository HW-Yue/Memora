# 清理计划：删除 ADR-0011 之后不再需要或已明确废弃的实现

状态：**已归档**（2026-09-20）。针对旧自研引擎代码库的删除清单；`rewrite/adr0011`
重写后那些包已不存在。当前工作见[执行计划](../../planning/execution-plan.md)。

原状态：计划（2026-09-13），A 组待授权开删，B 组待裁定。
依据：[ADR-0011](../../decisions/0011-pure-storage-engine-tables-everything.md)、
[Route 配套表](../../product/route-companion-table.md)、[双向链接](../../product/row-links.md)、
[数据行的生命周期](../../product/row-lifecycle-successor.md)、

原则：不破不立。被新形态取代的实现不留兼容层、不留「暂时还能用」的旧路径；
删除窗口内对应产品能力**不可用**，由后续 Feature 在新形态上重建。
本计划**覆盖** legacy-code-boundary「删除规则」中「先证明替代」的要求——
替代已由上面几份文档定下，不再以旧实现可用为前提。

## 不删（有现役职责，替代到位后随对应 Feature 删）

| 结构 | 为什么现在不能删 |
|---|---|
| 版本树 `versions` 与 `history:<tableID>` 树 | **Row 正文就存在它们的叶子里**（`currentrowindex` 只存 Locator，不带正文）。删了等于删数据。先把正文搬进表树（ADR-0011 第 3 步），再删 |
| change 树、`nativechange` | 变更归属与 binlog／灾难恢复链依赖它；change log 表化（第 4 步）后删 |
| objects 树 | 仍持有 Catalog 正文；A1、A3 删的只是其中的 Route 与 Relation 族 |
| 全文索引树 | ADR-0011 里归属 Deferred |
| `store/objectlock` | Row 热路径的快速失败；是否随「写串行」一起删另议 |
| 发布／安装工具（release、install、publication） | 与 ADR-0011 无关，产品分发在用 |

## B 组：要你裁定

**B1. 老库兼容链（约 −1.8 万行）**：记录日志 `store/native` 的归档职责、
`pagestoremigration` 里 v1–v7 旧 generation 的读取与升级、`nativemigration`、
`instanceupgrade`、`compat/sqlite-migrator`。
不需要老库能升级上来的话，这一整块都可以删，generation 只保留当前格式，
后续每步的格式变化也不再写升级路径。

**B2. 冻结的评测设施（约 −1.2 万行）**：answer benchmark／evaluation／corpus、
retrieval scorer、agentmetrics、storygate 与对应 cmd。
[ADR-0010](../../decisions/0010-small-scale-high-quality-evaluation.md) 定的是
「Deferred，冻结保留，不删」。它们大量依赖旧 Route 语句，删与不删都要改。
`internal/agent`（ADR-0009 的薄 Agent Loop）是产品方向，不在此列。
