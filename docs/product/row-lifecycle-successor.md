# 数据行的生命周期：原地修改、废弃与接替、懒更新

状态：**方向性结论**（2026-09-13；2026-09-21 修订删除与 history 归属）。
分层前提见 [ADR-0011](../decisions/0011-pure-storage-engine-tables-everything.md)；
语义节点的废弃与接替见 [Route 配套表](./route-companion-table.md)，本文把同一套规则扩展到数据行。
修订两处：**删除**改为[归档后物理删除](./row-delete-archive.md)；
拆分／合并后**新行的 history 指向来源 history**，见 [history 谱系](./history-lineage.md)。

## 一句话

值变了，身份不变：原地改，写 history。
身份变了（拆分、合并）：旧行标废弃，写明接替者，引用懒更新；新行的 history 指向来源 history。
删除不再是废弃：归档后物理删除，见[行删除](./row-delete-archive.md)。

## 两类变化，两种做法

| 场景 | RowID | 做法 |
|---|---|---|
| 改字段值 | 不变 | 一个事务内：原地 UPDATE 主表（revision +1），追加 history 表 |
| 拆分（一变多） | 变 | 一个事务内：写入新行，旧行置 `superseded`、**revision 不推进**，`successor_ids` 列出全部新行；新行 history 指向旧行 history |
| 合并（多变一） | 变 | 一个事务内：写入新行，各旧行置 `superseded`、**revision 不推进**，`successor_ids` 指向新行；新行 history 指向各旧行 history |
| 删除 | — | **已改**：归档后物理删除行、叶子、剪掉变空的父节点与 history，见[行删除](./row-delete-archive.md) |

身份变化的 history 与 revision 口径见 [history 谱系](./history-lineage.md)：源行 revision 不推进，
`(row_id, revision)` 不留空洞；`superseded` 状态与 `successor_ids` 同时存在。

**不做**「每次修改都新写一行、旧行废弃」：那会让每次编辑都换 RowID，
所有引用每次都过期，接替链无限变长。懒更新只服务于低频的身份变化。

废弃行仍留在主表；Agent 默认的 `SELECT`、列表与检索不返回废弃行。

## 引用有哪些

一行数据可能被这些东西指着，身份变化后它们都会过期：

- 语义叶子上的 `row_id`；
- 业务行上的 `route_leaf_id`（一行只占一个叶子）；
- 数据行之间的双向链接（规格另写）；
- Agent 上下文里还拿着的旧 RowID。

## 懒更新

身份变化的那次写**只改被拆／被合的行本身**，不去追着更新所有引用，
所以不会因为引用多而阻塞当前 Agent 任务。引用在之后按需修复。

**删除是例外，不走懒更新**：行被[归档式删除](./row-delete-archive.md)时，同一个事务里
按被删行自己的 `links` 倒推，把对面那一面直接摘掉，不留悬空链接。

**修复队列已落地**（2026-09-21）：拆分／合并那次事务会把所有指向源行的链接端点写进
`mem_repairs`（见[行链接](./row-links.md)「修复队列」），所以懒更新不再只是规范上的说法，
崩溃后也能接着修。出队与读侧标记见那里的 M6b-2。

### 读到过期引用

- 读的时候在内存里沿 `successor_ids` 解析出答案，立即返回，
  **不在读路径上同步写库**——写事务串行，读里写会被写锁卡住；
- 同时把「这条引用待修复」放进修复队列；
- 接替链设跳数上限防环；修复完成后引用直接指向链尾。

### 过期引用一律指向全部接替者

合并与拆分同一条规则，不做语义判断，修复完全机械：

- 合并：接替者只有一个，引用改指它；
- 拆分：引用改指**全部**接替者；
- 读到过期引用时同样返回全部接替者，不要求 Agent 选定。

各类引用的改法：

| 引用 | 修复 |
|---|---|
| 数据行之间的双向链接 | 一个事务里改两面：旧行去掉反向链接，每个接替者加上 |
| 业务行上的 `route_leaf_id` | 旧叶子换成修复后的叶子 |
| 叶子上的 `row_id` | 见下 |

**叶子指向被拆分的行**：一个叶子最多挂一行，装不下多个接替者。
修复时旧叶子置 `deprecated`，在同一父节点下为每个接替者建一个新叶子，
旧叶子的 `successor_ids` 指向这些新叶子——与 [Route 配套表](./route-companion-table.md)
的节点废弃规则一致。新叶子超过扇出上限时，按语义树的拆分阈值处理。
合并时接替者唯一，直接改叶子的 `row_id`。

这条旧叶子**有接替者，所以不参与「变空即物理删除」**：它是树外旧 `route_id` 的解析入口
（2026-09-21 明确）。没有接替者的空壳才清。

### 后台修复

- 双向链接两面都存，废弃行自己就知道谁在指它（反向链接 + `route_leaf_id`），
  后台直接拿它当待办清单，不必等查询命中；
- 查询命中的过期引用优先进队列。

### 挂载关系

- 一个叶子最多挂一个活跃 Row（[写入形态](./write-model.md) §4.4）；
- **一行只占一个叶子**（`route_leaf_id` 是单值，2026-09-21 修订）。
  因此叶子这一侧的引用是单数：被拆的行，它的旧叶子置 `deprecated` 后按接替者各建一个新叶子
  （见上），而不会出现「一个引用改指多个叶子」。

### 废弃行暂不回收

**仅指拆分／合并产生的 `superseded` 行**：它们留在主表，暂不物理删除；
回收的触发条件与保留期以后再定。**删除不走这条**——删除是
[归档后物理删除](./row-delete-archive.md)。
