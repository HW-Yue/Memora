# 数据行的生命周期：原地修改、废弃与接替、懒更新

状态：**方向性结论**（2026-09-13），标「候选」的条目待确认。
分层前提见 [ADR-0011](../decisions/0011-pure-storage-engine-tables-everything.md)；
语义节点的废弃与接替见 [Route 配套表](./route-companion-table.md)，本文把同一套规则扩展到数据行。

## 一句话

值变了，身份不变：原地改，写 history。
身份变了（拆分、合并、删除）：旧行标废弃，写明接替者，引用懒更新。

## 两类变化，两种做法

| 场景 | RowID | 做法 |
|---|---|---|
| 改字段值 | 不变 | 一个事务内：原地 UPDATE 主表（revision +1），追加 history 表 |
| 拆分（一变多） | 变 | 一个事务内：写入新行，旧行置 `deprecated`，`successor_ids` 列出全部新行 |
| 合并（多变一） | 变 | 一个事务内：写入新行，各旧行置 `deprecated`，`successor_ids` 指向新行 |
| 删除 | — | 置 `deprecated`，`successor_ids` 为空 |

**不做**「每次修改都新写一行、旧行废弃」：那会让每次编辑都换 RowID，
所有引用每次都过期，接替链无限变长。懒更新只服务于低频的身份变化。

废弃行仍留在主表；Agent 默认的 `SELECT`、列表与检索不返回废弃行。

## 引用有哪些

一行数据可能被这些东西指着，身份变化后它们都会过期：

- 语义叶子上的 `row_id`；
- 业务行上的 `route_leaf_ids`（一行可以挂在多个叶子下）；
- 数据行之间的双向链接（规格另写）；
- Agent 上下文里还拿着的旧 RowID。

## 懒更新

身份变化的那次写**只改被拆／被合的行本身**，不去追着更新所有引用，
所以不会因为引用多而阻塞当前 Agent 任务。引用在之后按需修复。

### 读到过期引用

- 读的时候在内存里沿 `successor_ids` 解析出答案，立即返回，
  **不在读路径上同步写库**——写事务串行，读里写会被写锁卡住；
- 同时把「这条引用待修复」放进修复队列；
- 接替链设跳数上限防环；修复完成后引用直接指向链尾。

### 合并与拆分的区别（候选）

- **合并**没有歧义：接替者唯一，后台自动改指；
- **拆分**有歧义：一条引用该跟哪个接替者走需要语义判断，代码不猜。
  读到时返回全部接替者并标明「引用已过期，接替者 N 个」，
  由 Agent 在当前任务里顺手选定；选不出就保持原样，不硬修。

### 后台修复与回收（候选）

- 双向链接两面都存，废弃行自己就知道谁在指它（反向链接 + `route_leaf_ids`），
  后台可以直接拿它当待办清单，不必等查询命中；
- 修一条链接在一个事务里改两面：旧行上去掉反向链接，接替者上加上；
- 废弃行的入向引用清空后才能物理回收，否则主表里的废弃行只增不减。
