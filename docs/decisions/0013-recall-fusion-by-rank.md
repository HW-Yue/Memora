# ADR-0013：两路召回按名次融合，名次不外露

状态：Accepted，2026-09-21。**第 5、6 条的字段清单已被
[ADR-0015](./0015-recall-exposes-position-provenance.md)（2026-09-22）修订：位置出处 `arms` 可外露，
分数、距离、名次与相关性解释仍然不可。** 修订 [ADR-0012](./0012-row-vector-leaf-path.md) 里
"分数与距离不外露；不设置或调优融合权重"的表述：**名次可内用，不可外露；权重仍然不可调**。

## 背景

关键词与向量两路同时给出时，原来是**并集**：各取候选、按位置去重、按"表名 + 路径"**字典序**
输出，`LIMIT` 截断。这个顺序与相关性无关——一个主打准确检索的产品，"前 10 条"不该由表名和
路径字符串决定。

关键词臂当时甚至**故意不用** FTS rank，`ORDER BY u.unit_no`（插入序），理由是"免得被误当成
相关性判断"。向量臂内部有距离序，但也只用来选够 `LIMIT` 条。

## 决定

1. **两臂各自按自己的相关性序取候选**：向量走 vec0 距离（近者在前，平分比 `unit_no`）；
   关键词走 FTS5 的 **BM25**（好者在前，平分比 `unit_no`）。这个序就是各臂的**名次**来源。
2. **融合用 RRF**：`score = Σ_臂 1 / (k + rank_臂)`，`k = 60`（原论文取值，**不是可调旋钮**）。
   两路都找到的位置因此排在只有一路找到的前面。
3. **平分回落到"表名 + 路径"字典序**。召回不返回分数，调用方无法察觉顺序是否漂移，
   所以同样的查询在未变的库上必须给出完全一样的列表——确定性测试继续钉住这条。
4. **`LIMIT` 仍是输出截断**：两臂各取多少是内部候选深度，不是契约；`LIMIT` 截断融合后的列表，
   与单臂同义。单臂语句的顺序也用同一套规则（一路参与的融合 = 该臂自己的序 + 字典序平分）。
5. **名次只在内里用，不出门**：响应仍然只有位置（每段 `name` + `route_id`，末端
   `kind`/`object_id`，以及 [ADR-0015](./0015-recall-exposes-position-provenance.md) 加的出处
   `arms`），**没有**分数、距离、名次、相关性解释或权重。**不外露原始距离**尤其重要：
   距离依赖 embedding space，跨模型不可比，外露会被读成可信度并用来设阈值。
6. **不做的**：不暴露每臂分数或名次（曾评估为"直接违约"：分数一旦进契约，模型与下游就会按它
   判断、按它截断、按它解释"为什么这条更相关"——正是旧 F21/F23 被撤销的路径，而外露字段删不掉）；
   不引入可调融合权重；不让融合结果充当答案（事实仍只由 SQL 回表产生）。

## 后果

- 关键词臂的排序从插入序换成 BM25，**单臂关键词召回的顺序随之改变**：`TestKeywordRecallScopeAndOrder`
  里"输出按路径有序"的说法作废，改为"按相关性排序、平分确定性"。
- 向量臂去掉尾部按路径排序，单臂向量召回的第一条现在是**真正最近的**。
- 融合只读名次，所以两臂"分"不可比这件事不再阻碍合并——**这正是不需要权重的理由**。
- `LIMIT` 的候选深度：今天两臂各取 `LIMIT` 条（向量内部会先探测 `max(2n, n+8)`）。
  加深候选（例如各取 `3×LIMIT` 再融合）是**实现细节**，不触碰契约，将来可单独评估。

## 风险

**契约腐蚀**：融合落地后，"引擎内部已经有分数/名次了"会成为下一次要求外露的论据。本 ADR 就是
为堵这条而写：**名次可内用、不可外露**；要改这条得再开一条 ADR，并承担上面第 6 条列出的代价。
